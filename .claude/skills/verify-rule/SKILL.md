# verify-rule

Fields of Fire のルール確認→実装（または修正）→ドキュメント同期、を一気通貫で行う。

## 対象PDF

- `FOF.pdf` — Series Rules 3rd Edition（コアルール全13章）
- `FoF_Deluxe_Normandy_Campaign.pdf` — ノルマンディーキャンペーン7ミッションの詳細
  （Higher HQ Event表・Enemy Force Package表・Fire Support表等、ミッションごとの数値はこちら）

どちらを見るべきかは依頼内容から判断する（コアメカニクスの一般則ならFOF.pdf、
ミッション固有の数値・R#テーブルならcampaign PDF）。

## 手順

1. **対象箇所の特定**
   - 節番号が分かっていればそれで良い。不明な場合は `python -c "import fitz; doc=fitz.open('FOF.pdf'); [print(t) for t in doc.get_toc()]"` でTOCを確認し、該当節を探す。
   - 既にこのセッション内でPDFテキストをscratchpadに抽出済みなら、再抽出せず `Grep` で該当キーワード・節番号を検索して使い回す。

2. **テキスト抽出**
   - `fitz` でページ範囲のテキストを抽出し、scratchpadのテキストファイルに保存してから `Read`/`Grep` で読む（コンテキストを圧迫しないため、直接大量ページを出力せずファイル経由にする）。
   - Windows端末なので `python3 -c "..."` 実行時は日本語・特殊文字の標準出力エンコードエラー（cp932）に注意。ファイルへの書き出しは `encoding='utf-8'` を明示する。

3. **画像レベルの確認が必要な場合**（カード印字の数値、地形カードの境界色など、テキスト抽出では拾えない情報）
   - `fitz` で該当カード画像を高倍率（`Matrix(6,6)`〜`Matrix(10,10)`）にクロップしてscratchpadにPNG保存し、`Read` で目視確認する。
   - 複数カードをまとめて見る場合は、`fitz` で新規PDFページを作って `insert_image` で並べた合成画像を作ると、1枚ずつ読むより効率的（このセッションで50枚のアクションカードR#確認に使った手法）。
   - 色や境界線の判定は早合点しない。既存コードの解釈と食い違う場合、どちらが正しいかを両方の証拠（画像・データ・過去の会話やメモの記憶）から慎重に判断する。ユーザーに「これ前に見て入れた記憶がある」等の情報があれば、それを優先的な手がかりにする。

4. **現在の実装との突き合わせ**
   - 関連する `js/` ファイルを `Grep`/`Read` で確認し、ルールと一致するか照合する。
   - 一致しない場合、原因が「データが間違っている」のか「データは正しいがコードの解釈（コメント・変換ロジック）が逆」なのかを切り分ける。後者の方が多い（このプロジェクトで実際に2回発生：NCMのdefHigh/defLow判定、terrain-data.jsのlosコメント）。

5. **実装・修正**
   - `Edit` で修正し、可能な場合はブラウザ（`run`/`verify`スキルまたはpreview系ツール）で実際に動かして確認する。乱数が絡む判定は複数回試行して分布を確認する。

6. **ドキュメント同期（CLAUDE.mdの明文ルールに従う）**
   - **ROADMAP.md** の該当章・節のステータス（✅/🟡/⬜/⛔）とメモを更新する。
   - **roadmap.html** の同じ項目のデータも同時に更新する（ズレさせない）。
   - メモ欄に「どのPDFのどのページ・節で確認したか」を残す（次回セッションで同じ調査をやり直さないため）。

7. **報告**
   - 結論・根拠（PDFのページ/節）・修正内容を簡潔にユーザーへ報告する。バグを見つけた場合は「見つけたバグ」として明示する。

## 注意事項

- 手順3の画像確認は時間がかかるので、テキストだけで判断できる内容なら省略してよい。
- ドキュメント同期（手順6）は省略しない。これを飛ばすと次回セッションでの再調査コストが発生する。
- PDFファイルはプロジェクトルート直下にある想定（`FOF.pdf`, `FoF_Deluxe_Normandy_Campaign.pdf`）。
